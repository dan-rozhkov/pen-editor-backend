# Аудит бэкенда pen-editor-backend

Дата: 2026-06-10. Объём: весь `src/` (~2000 строк) — `index.ts`, `config.ts`, `routes/`, `ai/`, `services/`, `plugins/`, `logging.ts`.

Статусы: ✅ исправлено · ⬜ открыто.

## 🔴 Высокий приоритет (безопасность и деньги)

### 1. ⬜ Нет аутентификации и rate-limiting
`/api/chat` и `/api/upload-image` открыты всем. Это прокси к платному OpenRouter API: любой, кто дотянется до сервера, сжигает токены и заливает файлы в S3. Минимум — API-ключ/токен на роуты и `@fastify/rate-limit`.
*Отложено осознанно — закрыть до публичного деплоя.*

### 2. ✅ Клиент сам выбирал модель без валидации
`chat.ts` / `provider.ts`: поле `model` из тела запроса передавалось в OpenRouter как есть — кто угодно мог запросить самую дорогую модель.
**Исправление:** allowlist моделей — `OPENROUTER_MODEL` + env `OPENROUTER_ALLOWED_MODELS` (comma-separated); неразрешённая модель → 400.

### 3. ✅ CORS отражал любой origin с `credentials: true`
`plugins/cors.ts` (`origin: true`) плюс ручные заголовки в `chat.ts` на hijacked-ответе: `Access-Control-Allow-Origin: <любой Origin>` + `Allow-Credentials: true` — классическая уязвимая конфигурация. Не было `Vary: Origin`.
**Исправление:** env `CORS_ALLOWED_ORIGINS` (comma-separated) используется и плагином, и ручными заголовками; `Allow-Credentials` убран (cookies не используются); добавлен `Vary: Origin`. Пустой список = разрешить всё (только для локальной разработки).

### 4. ✅ Загрузка SVG → stored XSS; MIME-тип не проверялся по содержимому
`routes/upload.ts`: `image/svg+xml` был разрешён — SVG может содержать `<script>`, а файл кладётся в S3 с `ACL: public-read`. MIME-тип брался со слов клиента (`file.mimetype` / data URI) без проверки магических байтов — под видом `image/png` можно было залить что угодно.
**Исправление:** SVG исключён; тип определяется сниффингом сигнатуры файла (png/jpeg/gif/webp), заявленный клиентом MIME игнорируется; не распознанный файл → 400.

## 🟠 Средний приоритет (корректность и надёжность)

### 5. ✅ Отключение клиента не останавливало генерацию
`chat.ts`: в `streamText` не передавался `abortSignal` — если пользователь закрыл вкладку, модель продолжала крутить до 12–15 шагов с тулзами.
**Исправление:** `AbortController`, срабатывающий на `close` ответа при `!writableEnded`, прокинут в `streamText` как `abortSignal`; добавлен `onAbort`-лог.

### 6. ✅ Синтетические skill-сообщения ломали `convertToModelMessages`
`chat.ts`: в массив UIMessage вставлялись сообщения в формате *ModelMessage* (`role: "tool"`, `content: [{type: "tool-call"…}]` без `parts`). Проверка по исходникам AI SDK v6 подтвердила: `role: "tool"` бросает `MessageConversionError: Unsupported role`, а assistant-сообщение без `parts` молча выбрасывается — любая `/skill`-команда падала с 500.
**Исправление:** инъекция заменена на валидный UIMessage c партом `type: "dynamic-tool"`, `state: "output-available"` — конвертер разворачивает его в assistant tool-call + tool result (проверено runtime-тестом на `convertToModelMessages`).

### 7. ⬜ Глобальный error handler отдаёт наружу `error.message`
`index.ts`: для любых 500-х внутренние детали (пути, ошибки SDK) уходят клиенту. Для `statusCode >= 500` отдавать generic-сообщение.

### 8. ✅ `.env.example` устарел
Были `OPENAI_*`-переменные, а `config.ts` требует `OPENROUTER_*` — сервер с примером из коробки не стартовал.
**Исправление:** файл переписан под реальные переменные, включая `REFERO_API_KEY`, `S3_*`, `OPENROUTER_ALLOWED_MODELS`, `CORS_ALLOWED_ORIGINS`.

### 9. ⬜ MCP-кэш не восстанавливается после деградации
`ai/mcp.ts`: запись из кэша удаляется только если упало *первоначальное* подключение. Если клиент Refero умер позже (сеть, истёкший токен), последующие запросы вечно используют мёртвый клиент, а research-режим тихо ломается.

### 10. ⬜ `get_style_guide` и `get_style_guide_tags` — заглушки
`ai/tools.ts`: на любые теги/имя возвращается один и тот же захардкоженный стайлгайд. Модель получает фиктивные данные, считая их реальным поиском. Реализовать или убрать.

### 11. ⬜ Любое сообщение, начинающееся с `/`, ломает чат
`chat.ts` + `ai/skills.ts`: `"/как дела"` или вставленный путь `/usr/...` → 400 «Unknown skill». Лучше при неизвестном «скилле» пропускать сообщение как обычный текст.

### 12. ⬜ Подсчёт операций `batch_design` по строкам неточен
`ai/tools.ts`: одна операция с многострочным значением (например, `htmlContent` с переносами) считается как несколько и ложно упирается в лимит 25.

## Дополнение: фронтенд (вне исходного скоупа)

### ✅ XSS через `htmlContent` embed-нод
Обнаружено при обсуждении пункта 4: `InlineEmbedEditor` монтирует `htmlContent` как живой DOM (shadow DOM изолирует стили, но не скрипты) — `<img onerror=...>` / `<svg onload=...>` исполнялись в origin приложения. Вставка SVG на канвас при этом безопасна (парсится в `path`-ноды без исполнения).
**Исправление (в репо `pen-editor`):** добавлен DOMPurify; `sanitizeEmbedHtml` (`src/utils/sanitizeEmbedHtml.ts`) вызывается в `mountHtmlWithBodyStyles` и `normalizeHtmlForEmbedRender`. Сохраняются `<style>`, инлайн-стили, SVG, data-URI картинки, `<slot>` и `<c-*>`-теги компонентов; вырезаются скрипты, обработчики событий и iframe. Проверено в браузере (Puppeteer) на 10 кейсах.
