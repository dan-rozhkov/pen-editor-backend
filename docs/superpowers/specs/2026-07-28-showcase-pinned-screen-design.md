# Showcase: выбор экрана, который идёт первым в ленте

**Дата:** 2026-07-28
**Репозиторий:** `pen-editor-backend` (фронт не затрагивается)

## Проблема

Витрина (`/`) — плоская лента: **каждый экран прогона это отдельная карточка**
(`pen-editor/src/components/showcase/ShowcasePage.tsx:155`), порядок задаётся
исключительно `ORDER BY created_at DESC, id DESC` в `listScreens`
(`src/showcase/store.ts:141-169`). Понятия «обложка прогона» нет, и нет никакого
способа сказать «вот этот экран должен встречать посетителя первым». Более того,
`publishScreens` вставляет строки последовательно, поэтому внутри одного прогона
лента показывает экраны **в обратном порядке** — последний нарисованный сверху.

## Решение

Один **закреплённый** (pinned) экран, который всегда идёт первым во всей ленте,
независимо от даты. Закрепление эксклюзивно: новый пин снимает предыдущий, так
что «первый экран» — всегда ровно один и в БД нет состояния, требующего разбора.

Отвергнутые альтернативы:

- *Группировка по `run_id` в карточку-прогон с обложкой* — ближе к слову
  «превью», но это новая агрегация в API, новый лайтбокс/карусель на фронте и
  переделка масонри. Несоразмерно задаче «выбрать, что показывать первым».
- *Колонка `screen_index` и сортировка внутри прогона* — чинит обратный порядок
  внутри прогона, но не даёт вынести конкретный экран наверх витрины.

### Данные

Миграция `src/analysis/migrations/004_showcase_pin.sql`:

```sql
ALTER TABLE showcase_screens ADD COLUMN IF NOT EXISTS pinned_at TIMESTAMPTZ;
CREATE INDEX IF NOT EXISTS showcase_screens_published_pinned_idx
  ON showcase_screens ((pinned_at IS NOT NULL) DESC, created_at DESC, id DESC)
  WHERE published;
```

`pinned_at` — таймстемп, а не булев флаг: он бесплатно отвечает на вопрос «когда
закрепили» и остаётся корректным, если эксклюзивность когда-нибудь ослабят.

### Порядок и пагинация

```sql
ORDER BY (pinned_at IS NOT NULL) DESC, created_at DESC, id DESC
```

Наивная замена только `ORDER BY` ломает кейсет-пагинацию: закреплённый старый
экран попадает на первую страницу, а затем **снова** на страницу, где его
`(created_at, id)` проходит по условию `< cursor`. Поэтому флаг пина входит в
курсор, и условие становится построчным сравнением:

```sql
((pinned_at IS NOT NULL), created_at, id) < ($1::boolean, $2::timestamptz, $3::uuid)
```

`false < true` в Postgres, поэтому DESC-порядок и построчный `<` согласованы.

Формат курсора: `p1|<createdAt>|<id>` / `p0|<createdAt>|<id>` (base64url).
Декодер продолжает принимать старый двухполевой формат `<createdAt>|<id>`,
трактуя его как `pinned=false` — это корректно для любой страницы ≥2 и не роняет
вкладку, открытую до деплоя.

### Точки управления

Write-API у витрины нет и авторизации тоже — всё управление остаётся CLI, как и
остальной пайплайн.

1. **Манифест `showcase:ingest`**: у экрана появляется `cover?: boolean`.
   Больше одного `cover: true` — ошибка парсинга манифеста.
2. **Флаг `--cover=<n>`** (1-based индекс экрана) у `showcase:ingest` и
   `showcase:generate`; для ingest перебивает манифест. Вне диапазона — ошибка.
3. **`npm run showcase:pin`** — постфактум, без перезаливки прогона:
   - `--screen <uuid>` закрепить;
   - `--clear` снять закрепление;
   - `--list` напечатать последние экраны (id, дата, тема, заголовок, пометка
     пина), чтобы было откуда взять uuid.

### Код

- `store.ts`: `ShowcaseScreen` получает `pinned: boolean`; новые методы
  `pinScreen(id): Promise<boolean>` (false, если строки нет) и `clearPin()`.
  `pinScreen` эксклюзивен: снимает все пины и ставит новый одним заходом.
- `publish.ts`: `PublishInput.coverIndex?: number` (1-based) и
  `PublishDeps.pinScreen`. После вставки экрана с этим индексом он закрепляется.
- `ingest.ts`: `cover` в `screenSchema` + резолв в `coverIndex`.
- Роут `/api/showcase` не меняется: `pinned` наружу не отдаётся, фронту он не
  нужен — порядок уже правильный.
